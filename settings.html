Lead Statuses
Drag to reorder. Represents a contact's current relationship to your company.
This is a real hierarchy, lowest at top to highest at bottom -- not just display order. Anything the app sets automatically (a form with a booking step, a new booking) can only move a contact FORWARD through this list, never backward: a BLACKLIST contact re-submitting a form stays BLACKLIST, an ENROLLED contact who mistakenly books another call stays ENROLLED. A person manually picking a status from the dropdown can still set it to anything, forward or back.

Summary Image
The instructions Claude gets before writing a lead's branded one-page summary card ("Generate Summary Image" button on the contact panel). It reads this contact's own application/custom field data and full conversation history alongside these instructions -- edit this to change what it emphasizes or how it's written, not the visual template (fonts/colors/logo are fixed in code).
Email Theme
The starting font, size, colors, padding, and width every new campaign and automation email is created with. Each one can still be overridden individually in its own editor (and reset back to this from there).
Reset existing emails to this theme
Overwrites every existing campaign's and automation send-email step's theme with the settings above -- individual overrides get wiped out. Save first if you changed anything.

Opt Out
Automatic opt-out rules, so no one keeps getting texted or emailed after they've asked to stop.
Stop Keywords
When a reply's ENTIRE text is one of these words (not just mentioned in a sentence), SMS is opted out for that contact. Their pipeline status (ENROLLED, BOOKED, etc.) is never touched by this — someone can still very much be an active student and just want texts to stop. A stop keyword only ever opts out SMS — it never affects email.
Blacklist Suppression
Anyone whose status is set to Blacklist — by hand, by a flow, or automatically by a trigger word — is opted out of SMS and unsubscribed from all emails sent from this CRM, and their conversation is hidden from the Inbox's default view (visible under the Hidden filter, no unread alerts). Applies no matter how the status was changed.
Blacklist Google Sheet
Every contact marked Blacklist is added to your blacklist sheet as a new row (FIRST, LAST, EMAIL, PHONE, DATE, matched by the tab's column headers; anyone already listed is skipped). Copy the link while you're on the blacklist tab so it includes that tab's gid. The sheet must be shared as Editor with the Google account this CRM uses for Sheets (the same one your Flows Google Sheet steps use). Each result is noted in that contact's conversation. This works whether or not the suppression switch above is on.
Blacklist Trigger Words
If a reply CONTAINS any of these words anywhere in it (not just as the entire message), the contact's status is set to Blacklist — with everything that brings (see Blacklist Suppression and the Blacklist Google Sheet above). Permanent: no reverse trigger.
Website & Page-Visit Tracking
Lets automations and SMS workflows trigger off a contact visiting a page on your site (Framer), after they've clicked a tracked email link.
Embed on your site
Paste this into a custom code / embed block on every page (e.g. Framer's Site Settings → Custom Code → End of <body> tag) you want page-visit triggers to work on. The full script is inlined here (not just a <script src> reference) so it works even where an external script tag wouldn't load reliably.
Ad Platform Link Tracking
Reference values for attributing traffic back to a specific ad. Meta and Google append these to your landing page URL when someone clicks an ad.
Paste into Meta Ads Manager → Ad Set → Tracking → URL Parameters.
Paste into Google Ads → Settings → Account-level (or Campaign-level) Tracking Template.
CRM Email Link Tagging
Nothing to configure here -- every link this CRM sends in email is automatically tagged ?el=email-<campaign-or-automation-name>, matching the el= convention already used on your ads, social posts, and YouTube links. SMS links are never auto-tagged -- add your own el= tag by hand if you want one, since this used to silently overwrite a manually-added tag.
Conversion Tracking (Meta & Google Ads)
Pushes real conversions (lead, booking, sale...) back to Meta and Google so their ad algorithms can optimize toward them -- matched by hashed email/phone, no click id needed. This is what Hyros used to do.
Meta
Not Connected
Same access token also powers "Add to Custom Audience" automation steps -- needs the ads_management permission, not just Conversions API access. Leads/bookings/sales route to whichever pixel matches the contact's Online/Gym type.
Google Ads
Not Connected
Reuses this app's existing Google OAuth client. Need a refresh token with Ads API access? Run node get_ads_token.js from the project folder and paste the result here.
Conversion Events
Define the events worth tracking. Nothing fires automatically -- wire each one into a Flow with a "Send Conversion Event" step wherever it actually happens (form submitted, booking created, status changed, etc).
Send Test Event
Fires against both platforms regardless of the event's own toggles, so you can check the connection before wiring anything real.
